VideoSplat

專案總覽（Project Overview）

VideoSplat 是一組以單張角色影像為起點的研究型工具鏈。它先透過 ComfyUI 與 MiniMax H3 產生角色 360 度環繞影片及遮罩，再將影片轉為可供 COLMAP 與 Brush 使用的多視角資料集，訓練 3D Gaussian Splatting（3DGS）角色。完成初始重建後，系統會以第一張已註冊影格建立固定的三維相機座標，渲染三個完整環與十二條 90 度相機路徑，並可再次透過 ComfyUI 在 latent 空間細化影像，產生已知相機姿態的第二階段 Brush/COLMAP 資料集。

本專案解決的核心問題，是把生成式影片提供的跨視角影格轉成可驗證、可重建且可追溯相機姿態的 3DGS 資料。研究計畫中的目標使用者是進行單張影像三維角色、多視角生成、3DGS 重建與後續 Gaussian-to-Mesh／角色動畫研究的工程師或研究者。

專案性質是以 Python 為主的研究工具鏈。五個主要步驟均以 Python 作為入口與流程控制，另包含 ComfyUI JSON 工作流；只有獨立的本機 Viewer 前端使用 JavaScript。它不是單一 library、常駐 service 或完整的一鍵式 app。

系統架構說明（Architecture Overview）

系統依資料責任分成五個管線階段與一個 Viewer。第一階段負責生成環繞影片與追蹤遮罩；第二階段負責抽幀、RGBA 清理、COLMAP 相機估計及品質驗證；第三階段以 Brush CLI 訓練初始 Gaussian PLY；第四階段固定 Gaussian，從第一個已註冊相機建立 canonical 座標、六個 anchors、三個環與十二條相機路徑；第五階段把路徑影片、參考圖及 camera JSON 送回 ComfyUI 細化，再輸出已知姿態的資料集。Viewer 讀取第四階段產生的 path_graph.json、相機 JSON、影像與 PLY，不參與訓練。

模組間以檔案系統交換資料，沒有共享 Python package。主要資料契約是影片、RGBA PNG、COLMAP text model、Gaussian PLY、逐幀 camera JSON、path_graph.json 及 Nerfstudio transforms.json。

系統流程說明（System Flow）

主要執行流程如下。第二階段 COLMAP 驗證至少要求 80% 影像註冊率、300 度相機弧，並限制相鄰相機步進；單組失敗時批次模式會記錄失敗並繼續其他組。第四階段會驗證固定半徑、路徑角度、共用 anchor、一致的相機內參、Front 重投影、mask 格式與影片尺寸；驗證未通過時會停止該資料集。第五階段可由既有生成影片續跑，也可使用 --prepare-only、--datasets-only 或 --consolidated-only 跳過部分流程。

安裝與環境需求（Installation & Requirements）

  1. 安裝 Python 3.9 以上版本。程式使用 argparse.BooleanOptionalAction、內建泛型型別與 Path 新式 API；原始檔未記錄實際測試的 Python 小版本。
  2. 安裝 FFmpeg 與 FFprobe，並將兩者加入 PATH。第二與第五階段會直接呼叫這兩個命令。
  3. 安裝 CUDA 版 COLMAP，將執行檔加入 PATH，或設定 VIDEOSPLAT_COLMAP。第二階段的 Python 套件可用 python -m pip install -r 2_colmap/requirements.txt 安裝。
  4. 準備支援本專案 flags 的 Brush CLI，並加入 PATH 或設定 VIDEOSPLAT_BRUSH_EXE。第四階段另需執行 python -m pip install -r 4_ply_ball_camera/requirements.txt，且 run.py 目前要求 Windows、CUDA compiler 與 Visual Studio 2022 C++ Build Tools。
  5. 為第一與第五階段啟動 ComfyUI。工作流實際使用 MiniMax H3、BiRefNet、SAM3、Sage Attention，以及第五階段的 MiniMax H3 latent encode/noise/decode 節點；所需模型檔名可在 1_suround_video/config.py 與兩個 workflow JSON 中查到。ComfyUI、custom nodes 與模型的精確版本尚未定義。

第一階段只需額外安裝 python -m pip install -r 1_suround_video/requirements.txt。XYZ Orbit_Viewer 的 Python 後端只使用標準函式庫；JavaScript 前端依賴鎖定於 XYZ Orbit_Viewer/package-lock.json，建置命令是 npm ci 後執行 npm run build。Node.js 的最低版本尚未在專案檔案中定義。

使用方式（How to Use）

以下命令均從 repo 根目錄執行。先為每個階段建立其 input/，再把前一階段的必要輸出複製或連結到下一階段；程式目前不會自動跨資料夾搬移產物。

  1. 將人物圖片放入 1_suround_video/input/，確認 ComfyUI 位於 http://127.0.0.1:8188，執行 python 1_suround_video/main.py。每位人物會得到主影片、mask 影片及選配的來源圖副本。
  2. 將每組主影片與檔名含 mask 的影片放在 2_colmap/input/<組別>/，執行 python 2_colmap/main.py。成功輸出位於 2_colmap/output/<組別>/brush_dataset_rgba_clean/。
  3. 將上一步資料集放到 3_360brush/input/<組別>/brush_dataset_rgba_clean/，設定 Brush CLI 後執行 python 3_360brush/main.py。輸出為 3_360brush/output/<組別>/<組別>.ply。
  4. 將單一 PLY、對應 COLMAP text model 與 registered images 放入 4_ply_ball_camera/input/；多人物時使用 input/<組別>/。執行 python 4_ply_ball_camera/run.py。完成後可執行 python 4_ply_ball_camera/scripts/validate_project.py 再驗證。
  5. 將第四階段的路徑影片放入 5_XYZ Orbit_Minimax/input/All/、camera paths 放入 5_XYZ Orbit_Minimax/input/paths/，並依 config.json 放置參考圖。先執行 python "5_XYZ Orbit_Minimax/main.py" --check，再執行 python "5_XYZ Orbit_Minimax/main.py"。

Viewer 需要第四階段輸出的 path_graph.json、anchors/、paths/ 及 PLY 放在 XYZ Orbit_Viewer/input/。先在 XYZ Orbit_Viewer/ 執行 npm ci 與 npm run build，再從 repo 根目錄執行 python "XYZ Orbit_Viewer/app.py"；預設網址為 http://127.0.0.1:8000/。

開發者指南（Developer Guide）

  1. 先讀根目錄 README 的三張圖，再讀各階段的 main.py 入口與同目錄設定檔。
  2. 追查資料格式時，依序閱讀 2_colmap/core.py、4_ply_ball_camera/src/source_camera.py、camera.py、pipeline.py、5_XYZ Orbit_Minimax/main.py。
  3. 修改相機 convention 時，必須同步檢查 COLMAP/OpenCV 的 +X right, +Y down, +Z forward、Nerfstudio/OpenGL 轉換，以及 JSON 中的 W2C/C2W；不可只改單一模組。
  4. 修改第四階段 render 或 mask 邏輯後，執行 scripts/validate_project.py，並檢查 validation.json、Front 重投影及 contact sheets。
  5. 修改第五階段 workflow 節點 ID 時，同步更新 config.json.workflow_nodes；修改 Viewer 前端後執行 npm test、npm run build 與 Python 後端測試。

新增資料處理階段時，應維持目前的檔案契約，並在輸出中保存可追溯 metadata；若改變 camera JSON、path_graph.json 或 transforms.json 結構，需同時更新第五階段與 Viewer 的讀取端。

已知限制與待辦事項（Limitations & TODO）

  • 授權條款尚未定義；在加入明確 LICENSE 前，第三方無法判定程式碼的再使用權利。
  • 端到端自動化測試尚未定義。現有測試只涵蓋第五階段部分相機轉換，以及 Viewer 的資料索引、HTTP server 與 path orientation。
  • 第三階段依賴支援特定 flags 的 Brush CLI；可取得的版本、建置方式與相容 commit 尚未在專案中定義。
  • 第四階段啟動器目前是 Windows 專用，會尋找 Visual Studio 2022，並預設 TORCH_CUDA_ARCH_LIST=12.0；其他平台的啟動方式尚未定義。
  • 第五階段輸出的 COLMAP points3D.txt 為空，因為該流程沿用已知相機姿態而不建立或虛構 3D 特徵點。

程式碼中未發現明確的 TODO、FIXME 或 XXX 標記；以上限制是從實際入口、設定、驗證與測試範圍整理出的未完成事項。

補充說明（Notes）

研究計畫將本流程定位為「生成式多視角影片結合傳統三維重建」的方法，並規劃與 TripoSplat、Hunyuan3D、TRELLIS 等直接式 Image-to-3D 方法比較多視角一致性、幾何正確性、外觀保持、重建品質、運算成本與可編輯性。比較實驗、Gaussian-to-Mesh、骨架綁定與角色動畫驗證尚未實作在此 repo 的主流程中。

原始研究計畫、人物影像、影片、模型權重、PLY、COLMAP database、Brush 訓練輸出及其他大型實驗產物未納入 repo。這些資料可能含個人內容或超出一般 GitHub 儲存容量；執行時應放在已被 .gitignore 排除的 input/、output/ 或模型目錄中。
